# 怎么读这份文档

参考页的每个部分都有固定位置。查一个类时，先看**属性表**确认构造时能写什么，再看**方法详情**确认怎么调用；其余区块各有分工，下表说明它们分别回答什么问题，以及为什么有的表格只出现在少数几个类页面上。

| 区块 | 内容 |
| --- | --- |
| 属性表 | 本类自己声明的字段：**属性名 / 类型 / 默认值 / 说明**。构造对象时把这些名字直接写进 `Class:New{ ... }` 的表里。 |
| 继承属性 | 本类没有重新声明、但通过父类继承可用的字段，折叠显示，标注来源类。 |
| 通用键 | **不属于任何类、但所有控件都能写**的键：结构键 `parent / children / name / classname / clientWidth / clientHeight`，几何键 `x / y / width / height / right / bottom`（[Control](#cls-Control) 起）。**完整表格只放在 [Object](#cls-Object)（结构键）和 [Control](#cls-Control)（结构键 + 几何键）这两个类页面上**，其余 26 个类页面只留一行指向它们的提示 —— 这些键对每个控件完全一样，重复 28 遍只会让页面变长。完整规则见 [New 里能写什么](#guide-newkeys)。 |
| 类索引速查 | 28 个类摊在一张表里横向对照：父类、本类 / 可用属性数、本类 / 可用方法数、皮肤块数、一句话职责 —— 用来先决定「该用哪个类」，再点进详情。见 [类索引](#class-index)。 |
| 属性 × 方法 | 回答两个常被问到的问题：**属性是不是只对某些方法有效**（不是，所有属性在任何实例上都能读写），以及**某个方法读写哪些字段**（每个类的「方法 → 字段」表，由源码静态扫描得出）。见 [属性 × 方法](#props-methods)。 |
| 方法读写字段 | 方法详情下面那排小方块（「源码里读写的字段」）**不是属性清单**，而是「这个方法体里出现过哪些 `self.x` / `obj.x`」的静态扫描结果：r 只读、w 只写、rw 读写、`_` 开头是内部字段。它只覆盖被这个方法直接碰到的字段，所以看起来「只列了一部分」。完整解释、图例、为什么不全、和属性表的区别，见 [**方法读写了哪些字段**](#guide-uses)。 |
| 换皮肤 | 11 套自带皮肤的实际字段、三种换法（全局 / 按类 / 单控件）、自定义一套皮肤，以及「为什么改完 theme 老控件不变」。教程见 [换皮肤](#guide-skins)，可运行案例见 `chili_demo_09_skins.lua`。 |
| 方法 / 函数 | `Class:Method(...)` 表示实例方法（用冒号调用，`self` 自动传入，参数表中省略 `self`）；`Class.Static(...)` 表示点号调用的静态函数。每个函数给出参数与返回值说明。 |
| 事件 | 以 `On*` 命名的属性是事件表，构造时写成 `OnClick = { function(self) ... end }`，触发时按顺序调用表中所有函数。 |
| 初始化时机 | widget 文件体在**加载阶段**就执行（那时 `WG.Chili` 还是 nil），类表要等 `api_chili.lua` 初始化后才有；widget 按 `layer` 升序初始化，所以用 Chili 的 widget 要把 `layer` 设成 `> 1000`。 |
| 可见性 | 顶层控件必须写 `parent = Chili.Screen0`；[Object:New](#fn-Object-New) 只在有 parent 时才 AddChild，孤儿控件不会被绘制也不会响应鼠标。 |
| 辅助模块 | `Handlers/`、`Headers/`、`core.lua`、`Themes/` 中不属于控件类的全局 / 表函数。 |
| 皮肤 | `Skins/*/skin.lua` 里每个控件可配置的皮肤字段（颜色、贴图、字体等），决定控件的实际外观。 |
